Core Web Vitals 2026: guía práctica para mejorar el SEO técnico

LCP, INP y CLS siguen siendo señales de ranking. Esta guía te muestra cómo medirlos, priorizarlos y corregirlos sin reescribir todo el sitio.

LG

Laura Gómez

Especialista SEO técnico

Los Core Web Vitals siguen siendo uno de los grupos de métricas de experiencia que Google usa en la búsqueda. En 2026, con INP consolidado como sustituto de FID, un sitio lento no solo pierde visitas: pierde posiciones en resultados competitivos.

Qué mide cada Core Web Vital

  • LCP (Largest Contentful Paint): cuánto tarda en pintar el elemento principal visible (hero, titular o imagen grande).
  • INP (Interaction to Next Paint): latencia percibida al interactuar con botones, menús y formularios.
  • CLS (Cumulative Layout Shift): cuánto se mueve el diseño mientras la página carga.

El objetivo de campo (CrUX) suele ser: LCP ≤ 2,5 s, INP ≤ 200 ms y CLS ≤ 0,1 en el 75% de las sesiones. Lab (Lighthouse) orienta; el dato real de usuarios es el que decide el ranking.

Cómo priorizar las correcciones

Empieza por el LCP del hero: precarga de la imagen principal, formato AVIF/WebP, CSS crítico inline y elimina render-blocking de terceros. Después ataca el INP: divide JavaScript largo, usa event handlers ligeros y evita tareas de más de 50 ms en el hilo principal. Para el CLS, reserva dimensiones explícitas en imgs/iframes y evita inyectar banners sobre el contenido.

Checklist rápida antes de publicar

  • Imagen hero con width/height y prioridad de carga.
  • Fuentes con font-display: swap y preload selectivo.
  • Sin scripts de terceros no esenciales en el head.
  • Layout con aspect-ratio en grid y cards.
  • Medir en Search Console → Rendimiento → Core Web Vitals.

Si tu web ya tiene buen contenido pero no crece en tráfico orgánico, revisa primero las métricas de campo: suelen ser el cuello de botella invisible.
