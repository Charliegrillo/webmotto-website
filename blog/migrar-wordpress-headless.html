Migrar WordPress a headless: cuándo vale la pena

Decapitar WordPress no es moda: es una decisión de rendimiento y experiencia de edición. Te contamos cuándo conviene y cómo migrar sin perder SEO.

DH

Diego Herrera

Arquitecto de soluciones

Headless con WordPress significa usar el CMS clásico como backend de contenido y consumirlo vía REST API o GraphQL desde un frontend moderno (Next, Nuxt, Astro…).

Cuándo tiene sentido

  • Necesitas frontends múviles (web + app + kiosco) sobre el mismo contenido.
  • El rendimiento del tema clásico ya no llega a buenos Core Web Vitals.
  • Tu equipo de producto quiere despliegues independientes del CMS.
  • Diseño altamente custom que pelea con PHP de plantillas.

Cuándo NO migrar

Si el sitio está estable, el tráfico depende de plugins de membership/e-commerce acoplados y no hay equipo frontend, el costo de headless supera el beneficio. WordPress monolítico bien optimizado sigue ganando a headless mal montado.

Checklist de migración sin perder SEO

  • Inventario de URLs y redirecciones 301.
  • Preservar slugs, fechas canónicas y schema Article.
  • SSG o SSR para HTML inicial con contenido real.
  • Migrar imágenes a CDN y mantener rutas o redirects.
  • Validar Search Console después del cutover.
  • Formación al equipo editor: cómo publicar en el nuevo flujo.

Costo de mantenimiento

Suma hosting del frontend, cache/CDN y coordinación de versiones CMS↔front. Compensa cuando el frontend cambia a menudo y el contenido cambia a otro ritmo.

Conclusión: headless es un acelerador de producto, no un trofeo de arquitectura. Migra por dolor concreto, no por tendencia.
